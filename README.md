# Monomorph

Header-only C11 macros that mimic high-level abstractions through monomorphisation: parametric types, type-constructor polymorphism, and type-class-style overloaded methods. Every instantiation is a concrete C type or function with a readable name, so there's no `void *`, no function pointers, and no runtime dispatch.

```
List(Str)                       →  ListǀStrǀ
eq(Str)                         →  eqǀStrǀ
contains(Matrix(int))           →  containsǀMatrixǀintǀǀ
List(Matrix(int))               →  ListǀMatrixǀintǀǀ
Pair(Str, int)                  →  PairǀStrꞏintǀ
```

## Example

The pieces below build a list and a matrix, an `eq` method, a `filter` that depends on `eq`, and a `contains` that works for any container type.

### Declaring type constructors and methods

`TYPE` declares a type constructor. `OVERLOAD` declares a method whose name depends on its type arguments, much like a type-class method. The comments give each method's signature.

```c
/* prelude.h */
#include <stdbool.h>
#include <stddef.h>
#include <stdlib.h>
#include "monomorph.h"

/* Type constructors */
#define List(T)         TYPE(List, T)
#define Matrix(T)       TYPE(Matrix, T)
#define Pair(T0, T1)    TYPE(Pair, T0, T1)      /* PairǀT0ꞏT1ǀ */

/* Overloaded methods */
#define eq(T)           OVERLOAD(eq, T)         /* bool    (T, T)         */
#define len(T)          OVERLOAD(len, T)        /* size_t  (T)            */
#define at(T)           OVERLOAD(at, T)         /* T'      (T, size_t)    */
#define filter(T)       OVERLOAD(filter, T)     /* List(T) (List(T), T)   */
#define contains(T)     OVERLOAD(contains, T)   /* bool    (T, T')        */
```

### Implementing instances

Implementations are written once against a type parameter `T` and stamped out per type by including the file after `#define T`. `filter` calls `eq(T)`, so it works for any `T` that has an `eq` instance, the C equivalent of an `Eq a =>` constraint, checked at compile time.

```c
/* list_impl.h: instantiate with #define T <type>. Requires eq(T). */
#ifndef T
#  error "list_impl.h: define T before including"
#endif

typedef struct List(T) { T *items; size_t n; } List(T);

static inline size_t len(List(T))(List(T) xs) {
  return xs.n;
}
static inline T at(List(T))(List(T) xs, size_t i) {
  return xs.items[i];
}

/* Keep the elements that are not equal to x. */
static inline List(T) filter(T)(List(T) xs, T x) {
    List(T) out = { malloc(xs.n * sizeof(T)), 0 };
    for (size_t i = 0; i < xs.n; i++)
        if (!eq(T)(xs.items[i], x))
            out.items[out.n++] = xs.items[i];
    return out;
}

#undef T
```

```c
/* matrix_impl.h: instantiate with #define T <type>. A 2x2 matrix. */
#ifndef T
#  error "matrix_impl.h: define T before including"
#endif

typedef struct Matrix(T) { T data[4]; } Matrix(T);

static inline size_t len(Matrix(T))(Matrix(T) m) {
  (void)m;
  return 4;
}
static inline T at(Matrix(T))(Matrix(T) m, size_t i) {
  return m.data[i];
}

#undef T
```

### Type-constructor polymorphism

An implementation can also be parameterised over a type constructor `F`, not just a type. `F(T)` applies it, and it appears by name in mangled identifiers such as `containsǀListǀStrǀǀ`. `contains` works for any container that provides `len(F(T))` and `at(F(T))`:

```c
/* contains_impl.h: instantiate with #define F <type constructor> and
   #define T <type>. Requires len(F(T)), at(F(T)) and eq(T). */
#if !defined(F) || !defined(T)
#  error "contains_impl.h: define F and T before including"
#endif

static inline bool contains(F(T))(F(T) xs, T x) {
    for (size_t i = 0; i < len(F(T))(xs); i++)
        if (eq(T)(at(F(T))(xs, i), x))
            return true;
    return false;
}

#undef F
#undef T
```

### Instantiation and dispatch

Instances can be written by hand for a specific type, or generated by including an implementation:

```c
/* main.c */
#include <stdio.h>
#include <string.h>
#include "prelude.h"

typedef const char *Str;

/* Instances written by hand */
static inline bool eq(int)(int a, int b) {
  return a == b;
}
static inline bool eq(Str)(Str a, Str b) {
  return strcmp(a, b) == 0;
}

/* Instances generated from a type parameter */
#define T Str
#include "list_impl.h"
#define T int
#include "matrix_impl.h"

/* Instances generated from a type-constructor parameter */
#define F List
#define T Str
#include "contains_impl.h"
#define F Matrix
#define T int
#include "contains_impl.h"

int main(void) {
    Str words[] = { "the", "cat", "sat", "on", "the", "mat" };
    List(Str) xs = { words, 6 };
    List(Str) ys = filter(Str)(xs, "the");
    Matrix(int) m = {{ 1, 2, 3, 4 }};

    printf("%zu\n", len(List(Str))(ys));             /* 4 */
    printf("%d\n", contains(List(Str))(ys, "cat"));  /* 1 */
    printf("%d\n", contains(List(Str))(ys, "the"));  /* 0 */
    printf("%d\n", contains(Matrix(int))(m, 3));     /* 1 */

    free(ys.items);
    return 0;
}
```

Each call names its instance, so dispatch happens in the preprocessor: `contains(Matrix(int))(m, 3)` is a direct call to `containsǀMatrixǀintǀǀ`. Using a method with no instance for a type fails at compile time. Instantiating `list_impl.h` for a `Point` type with no `eq(Point)`:

```
list_impl.h: In function ‘filterǀPointǀ’:
prelude.h:12:34: error: implicit declaration of function ‘eqǀPointǀ’; did you mean ‘filterǀPointǀ’? [-Werror=implicit-function-declaration]
   ...
list_impl.h:19:14: note: in expansion of macro ‘eq’
   19 |         if (!eq(T)(xs.items[i], x))
```

This is an error by default from GCC 14. On older versions, compile with `-Werror=implicit-function-declaration`.

## Naming scheme

| Character | Code point | Role |
|---|---|---|
| `ǀ` | U+01C0 LATIN LETTER DENTAL CLICK | opens and closes a parameter list |
| `ꞏ` | U+A78F LATIN LETTER SINOLOGICAL DOT | separates parameters |

Both are Unicode letters, so mangled names are ordinary C identifiers. Neither appears in normal type names, so every name decodes unambiguously: `ǀ` followed by a name opens a list, and `ǀ` followed by `ꞏ`, another `ǀ`, or the end of the name closes one.

## Requirements

- C11 or later, with UTF-8 source files.
- Tested with GCC 13 (`-std=c11`, `c17`, `c2x` with `-Wall -Wextra -pedantic`). GCC 10 or later is required for UTF-8 identifiers.
- Clang and MSVC are untested. MSVC needs `/utf-8` and the conforming preprocessor, `/Zc:preprocessor`.

## Limitations

- **Type arguments must expand to a single token:** a typedef name or a one-word type such as `int`. `unsigned int`, `float *`, and `struct foo` can't be pasted, so typedef them first, as with `Str` above.
- **Don't reuse macro names in typedefs.** Arguments are expanded before mangling, so if a type name is a macro in one file and a typedef in another, the two files produce different names and won't link.
- **1 to 8 type parameters.** Passing 9 to 16 produces a name containing `MONOMORPH_ERROR_more_than_8_type_parameters`. Zero is not diagnosed: `TYPE(List)` yields `Listǀǀ`.
- **Instantiate each type once per translation unit.** Including an implementation twice for the same parameters redefines its types. Non-`static` functions must be instantiated once per program, so split those implementations into a declarations header and a definitions file compiled once.
- **Locale.** GCC prints these names as-is only under a UTF-8 locale. Under `LANG=C` it prints escapes like `\U000001c0`, so set `LANG=C.UTF-8` in CI.
- **Fonts and editors.** Most coding fonts don't include `ǀ` or `ꞏ`, so editors draw them from a fallback font. VS Code highlights `ǀ` as ambiguous because it resembles `I`. To turn that off, add it to your settings:

  ```json
  "editor.unicodeHighlight.allowedCharacters": { "ǀ": true }
  ```

## API

| Macro | Expands to |
|---|---|
| `TYPE(Ctor, T, ...)` | mangled type name |
| `OVERLOAD(Name, T, ...)` | mangled method name |
| `MONOMORPH_TYPE`, `MONOMORPH_OVERLOAD` | same as above, always available |
| `MONOMORPH_TYPE_NAME`, `MONOMORPH_OVERLOAD_NAME` | mangled name as a string literal |

Define `MONOMORPH_NO_SHORT_NAMES` before including `monomorph.h` to leave out `TYPE` and `OVERLOAD` and use only the prefixed forms. `TYPE` and `OVERLOAD` mangle identically; the two names exist to document intent.
